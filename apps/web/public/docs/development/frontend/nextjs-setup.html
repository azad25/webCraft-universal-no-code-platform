Next.js Setup

Complete guide to setting up Next.js 15 for WebCraft frontend development

Overview

WebCraft uses Next.js 15 with App Router for the frontend. This guide covers the complete setup process, configuration options, and best practices for development.

Prerequisites:
  • Node.js 18+ (LTS recommended)
  • npm, yarn, or pnpm package manager
  • Basic React and TypeScript knowledge

Project Structure

Next.js follows a specific directory structure that WebCraft leverages for optimal organization:

apps/web/
├── app/                    # App Router directory
│   ├── (auth)/            # Route groups
│   │   ├── login/
│   │   └── register/
│   ├── (dashboard)/       # Dashboard routes
│   │   ├── apps/
│   │   ├── editor/
│   │   └── settings/
│   ├── setup/             # Setup wizard
│   ├── api/               # API routes
│   ├── globals.css        # Global styles
│   ├── layout.tsx         # Root layout
│   └── page.tsx           # Home page
├── components/            # Reusable components
│   ├── ui/               # UI components (shadcn/ui)
│   ├── widgets/          # Widget components
│   ├── editor/           # Editor components
│   ├── landing/          # Landing page components
│   └── shared/           # Shared components
├── lib/                   # Utility functions
│   ├── api-client.ts     # API client
│   ├── design-system.ts  # Design tokens
│   └── utils.ts          # Helper functions
├── hooks/                 # Custom React hooks
├── store/                 # Redux store configuration
│   ├── index.ts          # Store setup
│   └── slices/           # Redux slices
├── contexts/              # React contexts
├── types/                 # TypeScript types
└── public/               # Static assets

Installation & Setup

1. Install Dependencies

cd apps/web

# Using npm
npm install

# Using yarn
yarn install

# Using pnpm
pnpm install

2. Environment Configuration

Create a .env.local file in the apps/web directory:

# API Configuration
NEXT_PUBLIC_API_URL=http://localhost:8000
NEXT_PUBLIC_WS_URL=ws://localhost:8000

# Authentication
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=your-secret-key-here

# Feature Flags
NEXT_PUBLIC_ENABLE_REALTIME=true
NEXT_PUBLIC_ENABLE_ANALYTICS=true
NEXT_PUBLIC_ENABLE_AI_FEATURES=true

# Development
NODE_ENV=development
Note: All environment variables prefixed with NEXT_PUBLIC_ are exposed to the browser. Never put sensitive keys in these variables.

Next.js Configuration

next.config.js

/** @type {import('next').NextConfig} */
const nextConfig = {
  // Enable experimental features
  experimental: {
    serverComponentsExternalPackages: ['@react-dnd/backend'],
  },
  
  // Image optimization
  images: {
    domains: ['localhost', 'api.webcraft.dev'],
    formats: ['image/avif', 'image/webp'],
    remotePatterns: [
      {
        protocol: 'https',
        hostname: '**.amazonaws.com',
      },
    ],
  },
  
  // API proxy for development
  async rewrites() {
    return [
      {
        source: '/api/:path*',
        destination: `${process.env.NEXT_PUBLIC_API_URL}/api/:path*`,
      },
    ];
  },
  
  // Webpack configuration
  webpack: (config, { isServer }) => {
    if (!isServer) {
      config.resolve.fallback = {
        ...config.resolve.fallback,
        fs: false,
        net: false,
        tls: false,
      };
    }
    
    // Handle canvas for chart libraries
    config.resolve.alias.canvas = false;
    
    return config;
  },
  
  // TypeScript configuration
  typescript: {
    ignoreBuildErrors: false,
  },
  
  // ESLint configuration
  eslint: {
    ignoreDuringBuilds: false,
  },
};

module.exports = nextConfig;

API Client Setup

WebCraft uses a centralized API client for all HTTP requests:

// lib/api-client.ts
import axios from 'axios'
import { store } from '@/store'

const apiClient = axios.create({
  baseURL: process.env.NEXT_PUBLIC_API_URL || 'http://localhost:8000',
  timeout: 30000,
  headers: {
    'Content-Type': 'application/json',
  },
})

// Request interceptor - Add auth token
apiClient.interceptors.request.use(
  (config) => {
    const state = store.getState()
    const token = state.auth?.token
    
    if (token) {
      config.headers.Authorization = `Bearer ${token}`
    }
    
    return config
  },
  (error) => Promise.reject(error)
)

// Response interceptor - Handle errors
apiClient.interceptors.response.use(
  (response) => response,
  async (error) => {
    if (error.response?.status === 401) {
      // Handle token refresh or redirect to login
      window.location.href = '/login'
    }
    
    return Promise.reject(error)
  }
)

export default apiClient

Best Practices

Performance Optimization

  • Use next/image for optimized images
  • Implement dynamic imports for heavy components
  • Leverage Server Components for static content
  • Use loading.tsx for loading states
  • Implement proper error boundaries
  • Enable React Server Components where possible

Code Organization

  • Keep components small and focused
  • Use custom hooks for reusable logic
  • Separate business logic from UI components
  • Follow consistent naming conventions
  • Document complex components with JSDoc
  • Use TypeScript strictly - avoid any types

State Management

  • Use Redux for global application state
  • Use React Query for server state and caching
  • Use React Context for component-specific state
  • Avoid prop drilling - use context or state management
  • Normalize state structure for better performance

Common Issues & Solutions

Build Errors with React DnD

If you encounter build errors with React DnD, ensure you have the correct backend configured:

// Use HTML5Backend for web
import { HTML5Backend } from 'react-dnd-html5-backend'

// For touch devices, use TouchBackend
import { TouchBackend } from 'react-dnd-touch-backend'

// Configure in next.config.js
experimental: {
  serverComponentsExternalPackages: ['@react-dnd/backend'],
}

TypeScript Path Resolution

If TypeScript can't resolve your path aliases:

  1. Ensure tsconfig.json has correct paths configuration
  2. Restart your IDE/TypeScript server
  3. Clear Next.js cache: rm -rf .next

Hot Reload Not Working

Check that:

  • Files are in the correct directories
  • You're using the latest version of Next.js
  • No syntax errors in your code
  • Clear .next directory and restart

Environment Variables Not Loading

Remember that:

  • Only NEXT_PUBLIC_* variables are exposed to the browser
  • Restart the dev server after changing .env.local
  • Use .env.local for local development (not committed to git)
