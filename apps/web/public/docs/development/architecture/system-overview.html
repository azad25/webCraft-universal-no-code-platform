Architecture Overview

WebCraft uses a modern, domain-driven architecture with clear separation of concerns. The platform consists of a FastAPI backend (v2 API), Next.js frontend, and supporting infrastructure services.

Backend Architecture (API v2)

The v2 API uses a domain-driven design with 34 specialized domains:

Domain Structure

apps/api/src/
├── core/                    # Core infrastructure
│   ├── config.py           # Configuration management
│   ├── database.py         # Database connection
│   ├── security.py         # Authentication/Authorization
│   ├── redis.py            # Redis client
│   └── kafka.py            # Kafka client
├── common/                  # Shared utilities
│   ├── base_model.py       # Base SQLAlchemy model
│   ├── base_schema.py      # Base Pydantic schema
│   ├── base_service.py     # Base service class
│   └── exceptions.py       # Custom exceptions
├── domains/                 # Domain modules (34 domains)
│   ├── auth/               # Authentication
│   ├── apps/               # Application management
│   ├── pages/              # Page management
│   ├── widgets/            # Widget system
│   ├── widget_layers/      # Widget decomposition
│   ├── media/              # Media management
│   ├── ai/                 # AI services
│   ├── automation/         # Workflow automation
│   ├── collections/        # User databases
│   ├── crm/                # CRM functionality
│   ├── ecommerce/          # E-commerce
│   ├── payment/            # Payment processing
│   ├── analytics/          # Analytics
│   ├── seo/                # SEO optimization
│   ├── integrations/       # Third-party integrations
│   ├── notifications/      # Notifications
│   ├── webhooks/           # Webhooks
│   ├── mobile/             # Mobile APIs
│   ├── scrapers/           # Web scraping
│   ├── sdk/                # SDK generation
│   ├── graphql/            # GraphQL API
│   ├── export/             # Static export
│   ├── setup/              # Platform setup
│   └── ...                 # More domains
├── infrastructure/          # Infrastructure services
│   ├── websocket.py        # WebSocket manager
│   ├── logging.py          # Structured logging
│   ├── scheduler.py        # Task scheduler
│   └── services/           # External services
│       ├── cdn_service.py
│       ├── ssl_service.py
│       └── domain_service.py
├── middleware/              # HTTP middleware
│   ├── rate_limiting.py    # Rate limiting
│   ├── ai_crawler.py       # AI crawler optimization
│   └── seo.py              # SEO middleware
└── main.py                  # Application entry point

Domain Module Structure

Each domain follows a consistent structure:

domains/apps/
├── __init__.py      # Module exports
├── router.py        # FastAPI routes
├── service.py       # Business logic
├── schemas.py       # Pydantic schemas
└── models.py        # SQLAlchemy models (if needed)

Infrastructure Services

WebSocket Manager

Real-time communication with Redis pub/sub for horizontal scaling:

  • Room-based messaging
  • Presence tracking
  • Rate limiting
  • Automatic reconnection

Scheduler Service

Task scheduling for automations:

  • Cron expressions
  • Interval triggers
  • One-time execution

External Services

  • CDN Service: Cache management, purging
  • SSL Service: Certificate provisioning (Let's Encrypt)
  • Domain Service: DNS management

Middleware Stack

  • Rate Limiting: Request throttling per user/IP
  • AI Crawler: Optimized responses for AI bots
  • SEO: Meta tags, structured data injection
  • CORS: Cross-origin resource sharing
