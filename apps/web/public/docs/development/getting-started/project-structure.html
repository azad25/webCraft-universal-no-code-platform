Project Structure

Understanding the WebCraft codebase organization

Overview

WebCraft follows a monorepo structure with clear separation between backend and frontend code. This guide will help you navigate the codebase.

Root Directory Structure

webcraft-platform/
├── apps/
│   ├── api/              # FastAPI Backend
│   └── web/              # Next.js Frontend
├── k8s/                  # Kubernetes configurations
├── scripts/              # Setup and utility scripts
├── docs/                 # Documentation
├── docker-compose.yml    # Docker Compose configuration
├── .env.example          # Environment variables template
├── README.md             # Project README
└── architecture.md       # Architecture documentation

Key Directories Explained

Backend Core (apps/api/core/)

  • auth.py - JWT authentication, OAuth handlers
  • config.py - Environment configuration management
  • database.py - SQLAlchemy models and database session
  • module_system.py - Plugin system base classes
  • websocket.py - WebSocket connection handling

Backend Modules (apps/api/modules/)

Each module is a self-contained feature that can be enabled/disabled:

  • widgets.py - Widget library management
  • integrations.py - Third-party integrations
  • workflow.py - Automation workflows
  • ai_providers.py - AI service integrations

Backend Routers (apps/api/routers/)

FastAPI route handlers organized by feature:

  • Each router file contains related API endpoints
  • Routes are registered in main.py
  • All routes are prefixed with /api/v1

Backend Services (apps/api/services/)

Business logic separated from route handlers:

  • Services contain reusable business logic
  • Called by routers and other services
  • Handle database operations and external API calls

Frontend App Directory (apps/web/app/)

Next.js 14 App Router structure:

  • (auth)/ - Authentication pages (route group)
  • (dashboard)/ - Dashboard pages (route group)
  • [appId] - Dynamic route segments
  • layout.tsx - Shared layouts

Frontend Components (apps/web/components/)

React components organized by feature:

  • editor/ - Visual editor components
  • ui/ - Reusable UI primitives (Radix UI)
  • widgets/ - 60+ widget components

Frontend Store (apps/web/store/)

Redux Toolkit state management:

  • slices/ - Feature-based state slices
  • api/ - RTK Query API endpoints

File Naming Conventions

Backend (Python)

  • Files: snake_case.py
  • Classes: PascalCase
  • Functions: snake_case
  • Constants: UPPER_SNAKE_CASE

Frontend (TypeScript/React)

  • Components: PascalCase.tsx
  • Utilities: camelCase.ts
  • Hooks: useCamelCase.ts
  • Types: camelCase.ts or inline

Module System Structure

Understanding how modules are organized:

modules/
├── base.py              # Base module class
├── widgets.py           # Widget module implementation
└── custom_assets/       # Module with subdirectory
    ├── __init__.py
    ├── models.py
    └── schemas.py

Each module follows this structure:

  1. Inherits from BaseModule
  2. Implements metadata property
  3. Implements initialize() and shutdown() methods
  4. Optionally provides routes via get_routes()

Widget Structure

Widgets are organized in the frontend:

components/editor/widgets/
├── index.ts             # Widget exports
├── text-widget.tsx      # Text widget
├── image-widget.tsx     # Image widget
├── button-widget.tsx    # Button widget
└── ...                  # 60+ widgets

Each widget follows this pattern:

  • Accepts WidgetProps interface
  • Handles editing and preview modes
  • Exports default component
