REST API Reference

Complete reference for WebCraft's REST API endpoints

API Overview

WebCraft's REST API follows RESTful principles and provides comprehensive access to all platform features. The API is versioned and includes robust authentication, rate limiting, and error handling.

Base URL

# Production
https://api.webcraft.app/v1

# Development
http://localhost:8000/v1

API Versioning

The API uses URL versioning. Current version is v1. Breaking changes will result in a new version.

Authentication

WebCraft uses JWT (JSON Web Tokens) for API authentication. Include the token in the Authorization header:

Authorization: Bearer <your-jwt-token>

Obtaining a Token

# Login endpoint
curl -X POST https://api.webcraft.app/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "your-password"
  }'

Token Response

{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "expires_in": 3600,
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": "123e4567-e89b-12d3-a456-426614174000",
    "email": "user@example.com",
    "name": "John Doe"
  }
}

Projects

List Projects

GET /workspaces/{workspace_id}/projects
Authorization: Bearer <token>

Query Parameters:
- page: Page number (default: 1)
- per_page: Items per page (default: 20, max: 100)
- search: Search by name or description
- sort: Sort field (name, created_at, updated_at)
- order: Sort order (asc, desc)

Response:
{
  "data": [
    {
      "id": "proj_123e4567-e89b-12d3-a456-426614174000",
      "name": "Landing Page",
      "description": "Main landing page project",
      "settings": {
        "theme": "modern",
        "responsive": true
      },
      "created_at": "2024-01-01T00:00:00Z",
      "updated_at": "2024-01-01T00:00:00Z"

  "total": 1,

List Pages

GET /projects/{project_id}/pages
Authorization: Bearer <token>

Analytics

Get Page Analytics

GET /analytics/pages/{page_id}
Authorization: Bearer <token>

- start_date: Start date (YYYY-MM-DD)
- end_date: End date (YYYY-MM-DD)

Error Handling

Error Response Format

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Validation failed",
    "details": [
      {
        "field": "email",
        "message": "Email is required",
        "code": "REQUIRED"
      }
    ]
  },
  "request_id": "req_123e4567-e89b-12d3-a456-426614174000",
  "timestamp": "2024-01-01T00:00:00Z"
}

Common Error Codes

Code HTTP Status Description
UNAUTHORIZED 401 Invalid or expired authentication token
FORBIDDEN 403 Insufficient permissions
NOT_FOUND 404 Resource not found
VALIDATION_ERROR 422 Request validation failed
RATE_LIMIT_EXCEEDED 429 Rate limit exceeded
INTERNAL_ERROR 500 Internal server error

Pagination

All list endpoints support pagination using the following parameters:

  • page: Page number (default: 1)
  • per_page: Items per page (default: 20, max: 100)

Pagination Response

{
  "data": [...],
  "pagination": {
    "page": 1,
    "per_page": 20,
    "total": 100,
    "pages": 5,
    "has_next": true,
    "has_prev": false
  }
}
